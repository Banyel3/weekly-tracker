# Agent API — endpoints and tool definitions so Yumi (the Telegram bot, later Claude-powered) can operate the tracker

Date: 2026-11-04. Branch `feat/agent-api` off `main` db06ee1. Owner request: "create the API for it… so that an AI agent can run them (future of Yumi is that it's powered with an Anthropic API key)".

## Global Constraints

- **Auth.** New env `AGENT_API_TOKEN` (optional). Every route under `app/api/agent/**` requires `Authorization: Bearer <token>`. Missing env → `503 { "error": "agent api disabled: set AGENT_API_TOKEN" }`. Missing/wrong token → `401 { "error": "unauthorized" }`. Compare with `crypto.timingSafeEqual` on equal-length buffers. Helper `requireAgent(request)` in `lib/agent/auth.ts` returning `Response | null`. Existing UI routes stay unchanged and unauthenticated. `.env.example` gains `AGENT_API_TOKEN=` with a comment (`openssl rand -hex 32`); `docker-compose.yml` passes `AGENT_API_TOKEN: ${AGENT_API_TOKEN:-}`.
- **One operation layer, two entry points.** `lib/agent/ops.ts` exports `AGENT_TOOLS` (Anthropic tool-use definitions: `{ name, description, input_schema }`, JSON Schema written by hand next to the zod schema that validates the same input) and `runTool(name, input, now = new Date())`. `POST /api/agent/run` takes `{ "name": string, "input": object }`, validates with the tool's zod schema, returns `200 { "ok": true, "result": … }` or `400/404 { "ok": false, "error": string }`; unknown name → 404. `GET /api/agent/tools` returns `{ "tools": AGENT_TOOLS }` so a bot can pass it straight to the Messages API `tools` parameter. Convenience REST routes (below) call the same `runTool`.
- **Tools and inputs** (status strings are case-insensitive `backlog | this_week | in_progress | done`, mapped to the Prisma enum; priority `none | high | urgent`; dates are `YYYY-MM-DD` in Asia/Manila, with `today` and `tomorrow` accepted as sugar; outputs reuse `TaskDto`/`ProjectDto` unchanged):
  1. `get_today` → `{ date, weekday, dayIndex (Mon=1), week: {start,end}, digest: string (buildMorningDigest), overdue: TaskDto[], dueToday: TaskDto[], dueTomorrow: TaskDto[], laterThisWeek: TaskDto[], inProgress: number, wipLimit: number, openThisWeek: number, carried: number }` (reuse `loadDigestData`; add ids by loading the DTOs for the listed tasks).
  2. `get_board` → `listBoard(now)` plus `projects: ProjectDto[]`.
  3. `list_tasks` `{ status?: string[], project?: string (name, case-insensitive), due_from?, due_to?, query?: string (title/note contains, case-insensitive), archived?: boolean (default false), limit?: 1–100 (default 50) }` → `{ tasks: TaskDto[] }` sorted by `sortColumn`.
  4. `get_task` `{ id }` → `{ task: TaskDto, events: last 20 TaskEvent rows { type, at, from, to } }`; unknown → 404.
  5. `create_task` `{ title, note?, due?, priority?, status? (default backlog), project?: string (name; created with the first unused `PROJECT_COLORS` entry if missing), checklist?: string[] (≤20) }` → `{ task }` via `createTask`.
  6. `update_task` `{ id, title?, note?, due? (null clears), priority?, project? (name or null), checklist?: string[] }` → `{ task }` via `updateTask`; 404 when unknown; `RestoreFirstError` → 400.
  7. `move_task` `{ id, status }` → `{ task }` via `updateTask({ status })`; `done` sets `completedAt` through the existing path.
  8. `snooze_task` `{ id, days?: 1–60 (default 1), until?: date }` → sets `dueDate` to `until`, or to `max(today, dueDate) + days`; returns `{ task }`.
  9. `delete_task` `{ id }` → `{ deleted: true }` via `deleteTask` (events recorded as today); 404 when unknown.
  10. `restore_task` `{ id, status? (default backlog) }` → `{ task }` via `updateTask({ archived: false, status })`.
  11. `get_review` → `{ review: ReviewDto, summary: string }` via `getReview` + `buildWeeklySummaryText`.
  12. `list_projects` → `{ projects: ProjectDto[] }`.
- **Convenience REST routes** (same auth, same results): `GET /api/agent/today`, `GET /api/agent/board`, `GET /api/agent/tasks` (query params mirror `list_tasks`; `status` comma-separated), `POST /api/agent/tasks` (create_task body), `GET /api/agent/tasks/{id}`, `PATCH /api/agent/tasks/{id}` (update_task body without id), `DELETE /api/agent/tasks/{id}`, `POST /api/agent/tasks/{id}/{done|start|plan|backlog|snooze|restore}` (`start` = in_progress, `plan` = this_week; snooze body optional), `GET /api/agent/review`, `GET /api/agent/projects`.
- **Limits.** JSON bodies over 64 kB → 413. `limit` capped at 100. Every list query is bounded (`take`). `export const dynamic = "force-dynamic"` on every route.
- **Errors.** Always `{ "error": string }` (plus `"ok": false` on `/run`). Zod issues flattened into one readable string (`title: Required; due: must be YYYY-MM-DD`).
- **Reuse.** Use `lib/http.ts` helpers where they fit (`parseBody`, `isPrismaError`); never duplicate `createTask`/`updateTask`/`deleteTask`/`listBoard`/`getReview`/`loadDigestData`/`buildMorningDigest`; project lookup by name in one helper `findOrCreateProjectByName` in `lib/agent/projects.ts`.
- **Tests (vitest, mocked Prisma like `lib/tasks.update.test.ts`).** Auth: 503 without env, 401 with a wrong or missing token, 200 with the right one; `AGENT_TOOLS` every `input_schema` is valid JSON Schema (`type: "object"`, `properties`, `required` only lists keys that the zod schema requires) and every tool's documented example input (keep an `examples` map in the test) parses with its zod schema; `runTool` for each of the 12 tools (happy path + one error path each: unknown id, bad status string, bad date, limit > 100); status/priority/date sugar parsing; `snooze_task` date math (overdue task + days counts from today); `findOrCreateProjectByName` picks the first unused colour and is case-insensitive; `/run` route unknown tool → 404; one REST route test per verb family. Expect ≥ 60 new tests.
- **Docs.** `docs/agent-api.md`: auth, the 12 tools with input/output examples, REST table, error shapes, a curl walkthrough, and a 40-line Node example `docs/examples/yumi-loop.mjs` (not wired into the build) that fetches `/api/agent/tools`, runs one Messages API turn with model `claude-sonnet-5-5` and tool choice auto, dispatches each `tool_use` to `/api/agent/run`, and returns `tool_result`s — uses `@anthropic-ai/sdk` imported as a peer, with `ANTHROPIC_API_KEY`, `TRACKER_URL`, `AGENT_API_TOKEN` env. README gets a four-line "Agent API" section pointing at the doc. PRODUCT.md non-goals unchanged (single user; the bot is the same person).
- **Env rules.** Prefix every command with `TELEGRAM_BOT_TOKEN= TELEGRAM_CHAT_ID=`; no servers on 3000/3002; no docker. `npm run build` route table: `/` 281, `/review` 136, `/archive` 136 kB unchanged (server routes only).
- **Out of scope (note in the doc under "Later"):** attributing events to the bot (`TaskEvent.via` column), the Telegram command handler and the Claude loop itself (Phase 3 "Telegram digest with Done/Snooze"), Future-tasks tools, rate limiting beyond the body cap.
