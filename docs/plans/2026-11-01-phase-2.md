- **Design rules:** text contrast ≥ 4.5:1 on its surface (check `--muted-foreground` per preset; darken the surface or lighten the text in the preset file if a preset fails); every interactive element focusable with the `--ring` outline; status conveyed in text as well as color; 44px targets under `(pointer: coarse)`; motion 150ms ease-out on transforms/opacity/colors only, stagger ≤ 60ms, everything off under `prefers-reduced-motion`; one Aceternity effect at a time on screen (moving border on the WIP card when over limit; nothing else in Phase 2).
- **Data model (migration `phase2`, additive):** `enum Priority { NONE HIGH URGENT }`; on `Task`: `priority Priority @default(NONE)`, `checklist Json @default("[]")`, `rolloverCount Int @default(0)`, `completedAt DateTime?` with backfill `UPDATE "Task" SET "completedAt" = "updatedAt" WHERE status = 'DONE'`; new `model AppState { key String @id; value String; updatedAt DateTime @updatedAt }` for `lastSentOn:<job>` markers.
- **Checklist item:** `{ id: string, text: string (1–120, trimmed), done: boolean }`, max 20 items, validated by zod; order is array order.
- **API additions:** `GET /api/board` → `{ week, today, projects, tasks }` (tasks carry `priority`, `checklist`, `rolloverCount`, `completedAt`); `POST/PATCH /api/tasks` accept `priority`, `checklist`, `dueDate`, `projectId`; `PATCH /api/tasks/[id] { archived: false }` restores (Backlog, weekOf null, completedAt null); `PATCH /api/projects/[id] { name?, color? }` → 200/404/409; `DELETE /api/projects/[id]` → 204; `GET /api/archive?q=&before=YYYY-MM-DD&limit=8` (limit counts weeks; before is an exclusive week-start cursor; q filters title/note across all weeks) → `{ weeks: [{ start, end, tasks: TaskDto[] }], nextBefore: string | null }`; `GET /api/review` → `{ week: {start,end}, today, thisWeek: { planned, finished, inProgress, overdue, byProject: [{ projectId, name, color, planned, finished }] }, carried: [{ task: TaskDto, rolloverCount }], lastWeek: { start, end, planned, finished, carried, byProject } }`; `GET /api/health` → `{ ok, db: true, weekStart, lastRolloverAt }` (503 when the DB ping fails). All `force-dynamic`.
- **Status transitions:** `completedAt = now()` when status becomes DONE, `null` when it leaves DONE; `rolledBackAt = null` whenever status is present (unchanged); `rolloverCount` increments in the rollover's non-Done `updateMany`, resets to 0 in the archive `updateMany`.
- **Ordering in a column (server):** priority (URGENT, HIGH, NONE) → rolled-back first (Backlog) → dueDate asc nulls last → createdAt asc.
- **Scheduler:** keep `0 0 * * 1` rollover and `0 9 * * *` reminder; add `0 * * * *` idempotent rollover check; add `0 18 * * 5` `sendWeeklySummary()`; on startup, after the catch-up rollover, run `catchUpMissedJobs()`: if Telegram is configured and today (Manila) is Friday and now ≥ 18:00 and `AppState lastSentOn:summary != today` → send summary once; same for the 09:00 reminder. Every send writes its `lastSentOn:<job>` marker.
- **Friday summary text (exact):** line 1 `Week of <Mon d>: finished N of M · P in progress · O overdue`; then one line per project `Name f/p` joined by ` · `; then, if any, `Carried over twice or more: <titles joined by ", ">`.
- **Undo (exact):** 5-second window; latest action only; line copy `moved “<title>” to <Column> · undo`, `deleted “<title>” · undo`, `rescheduled “<title>” to <Mon d> · undo`. Delete is deferred: card hidden at once, `DELETE` sent after 5s unless undone, flushed with `fetch(..., { keepalive: true })` on `pagehide`. Move undo restores the full prior snapshot via one PATCH.
- **WIP limit:** constant `WIP_LIMIT = 3` in `lib/constants.ts`; In progress chip shows `n / 3` in `--alert` and the column border turns `--alert` when `n > 3`.
- **Copy (exact):** empty column `nothing here`; load error `couldn't load the board · retry`; save error `couldn't save · retry`; nudge line in dialog `Rolled over N weeks in a row. Split it, shrink it, or let it go.`; Phase 3 nav tag `soon`; theme chip `Theme · <Preset name>`.
- **Compose / deploy:** `app` published as `127.0.0.1:3000:3000`; `db` ports removed from the main file and provided by `docker-compose.dev.yml` (`5433:5432`); `restart: unless-stopped` on both; app healthcheck `curl -fsS http://localhost:3000/api/health || exit 1` (curl installed in the runner image) interval 30s, timeout 5s, retries 3, start_period 40s; `NEXT_TELEMETRY_DISABLED=1`; `scripts/backup.sh` (pg_dump via `docker compose exec -T db`, gzip, `backups/weekly-tracker-YYYYMMDD-HHMM.sql.gz`, prune older than `BACKUP_KEEP_DAYS`, default 30) and `scripts/restore.sh <file>`; `.env.example` adds `BACKUP_KEEP_DAYS=30`; README gains "Run on a laptop over Tailscale" (tailscale serve, Docker at boot, backups, move procedure) and keeps the one-command run.

## Task 7c: task event log + honest review insights

**Goal (owner request, 2026-11-03):** the review tells the truth about where the week's work came from and how it moved, without scoring or shaming. Example that motivated it: "finished 2 of 2 planned" where both tasks were carried from last week must read "finished 2 of 2 · both carried in from last week".

**Data (migration `events`, additive):**
```prisma
enum EventType { CREATED PLANNED UNPLANNED STARTED DONE REOPENED RESCHEDULED ROLLED_BACK ARCHIVED DELETED RESTORED }
model TaskEvent {
  id     String    @id @default(cuid())
  taskId String
  type   EventType
  at     DateTime  @default(now())
  weekOf DateTime? @db.Date
  from   String?
  to     String?
  @@index([taskId])
  @@index([at])
}
```
No foreign key (history survives deletes). `weekOf` = the Manila week start of `at`. Backfill in the migration SQL: `CREATED` from `createdAt` for every task; `DONE` from `completedAt` where not null; `ROLLED_BACK` from `rolledBackAt` where not null (`at` = rolledBackAt, one event even if `rolloverCount` > 1); `ARCHIVED` at `updatedAt` for archived rows.

**Writers (`lib/events.ts` `recordEvents(prisma, events[])`, called inside the existing mutation paths, `createMany`):**
- `createTask`: `CREATED`; plus `PLANNED` if status ≠ BACKLOG, `STARTED` if IN_PROGRESS, `DONE` if DONE.
- `updateTask` with a status change: BACKLOG→{THIS_WEEK, IN_PROGRESS, DONE} → `PLANNED`; →IN_PROGRESS → `STARTED`; →DONE → `DONE`; DONE→other → `REOPENED`; →BACKLOG from a week column → `UNPLANNED`. `from`/`to` carry the status names. A `dueDate` change → `RESCHEDULED` with `from`/`to` as ymd strings.
- Rollover: fetch affected ids first, then `updateMany` + `createMany` of `ROLLED_BACK` (non-Done) and `ARCHIVED` (Done) in one transaction.
- `deleteTask` → `DELETED` (before the row goes); restore (`archived:false`) → `RESTORED`.
- Project changes are not events.

**Insights (`lib/insights.ts`, pure, tested with fixtures; `getInsights(now)` loads tasks + the last 9 weeks of events):** added to `GET /api/review` as:
- `origin: { carriedIn, addedThisWeek, finishedCarried, finishedNew, addedAfterMonday }` where carriedIn = tasks planned this week that have a `ROLLED_BACK` at this Monday; addedThisWeek = planned this week with `CREATED` inside the week; addedAfterMonday = `PLANNED` events this week after Monday 23:59 Manila.
- `flow: { medianCreatedToDoneDays, medianInProgressDays, reopened }` from this week's `DONE` events (`CREATED`→`DONE`, last `STARTED`→`DONE`) and `REOPENED` count.
- `signals: { reschedules, reschedulesPerPlanned, avgOverdueDaysBeforeDone, rolledTwice, oldestBacklogAgeDays, midWeekRatio }`.
- `trend: [{ weekStart, planned, finished }]` for the last 8 ISO weeks (planned = distinct tasks with a `PLANNED` event in that week or archived with that `weekOf`; finished = `DONE` events in that week not followed by `REOPENED` of the same task in the same week).
- `pattern: string | null`, first matching rule in this order, neutral wording, no scores: (1) `you finish most on <Day> and <Day>` when two weekdays hold ≥ 50% of the last 8 weeks' `DONE` events; (2) `<N> tasks waited 2+ weeks before you started them` when N ≥ 2 from `CREATED`→`STARTED`; (3) `half of this week's tasks were added after Monday` when midWeekRatio ≥ 0.5 and planned ≥ 4; (4) `steady week: finished N of M` when planned ≥ 1; else null.
