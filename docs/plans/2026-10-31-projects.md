# Projects + dialog-first add — Implementation Plan

Date: 2026-10-31. Follows `docs/plans/2026-10-31-weekly-kanban.md` (shipped). Spec: the user's requests in chat on 2026-10-31, recorded here.

## Intent

1. Every `+ add` in a column opens the task dialog in create mode (status preset to that column). The inline quick-add goes away.
2. Tasks can belong to a **Project**: a name plus one of eight preset colors. The project shows on the card as a colored chip. Projects are created from inside the task dialog. No project filtering, grouping, editing or deleting yet (Phase 2).

## Phase 2 (noted, not built)

Redesign toward the Synchro reference (dribbble.com/shots/27058593): board occupies less of the page; a week calendar strip of due tasks above it; a left sidebar (project list with colors, counts, maybe Backlog); colored status chips per column; richer card chrome. Project filtering/grouping and project management (rename, recolor, delete) belong here.

## Global Constraints

All constraints from the shipped plan's Global Constraints still bind (timezone, date wire format, tokens, code style, no new deps, commit trailer `Co-Authored-By: Claude Fable 5.1 <noreply@anthropic.com>`). Additions:

- **Prisma:**
  ```prisma
  model Project {
    id        String   @id @default(cuid())
    name      String   @unique
    color     String
    createdAt DateTime @default(now())
    tasks     Task[]
  }
  ```
  and on `Task`: `projectId String?` with `project Project? @relation(fields: [projectId], references: [id], onDelete: SetNull)`. Migration name `projects`, additive only.
- **Color keys** (stored string; zod enum): `rose | amber | lime | teal | sky | violet | pink | slate`. CSS tokens in `globals.css` (OKLCH, dark-surface tuned): `--project-rose oklch(0.72 0.14 15)`, `--project-amber oklch(0.78 0.13 75)`, `--project-lime oklch(0.78 0.14 125)`, `--project-teal oklch(0.76 0.11 180)`, `--project-sky oklch(0.75 0.11 230)`, `--project-violet oklch(0.72 0.13 290)`, `--project-pink oklch(0.74 0.14 340)`, `--project-slate oklch(0.72 0.02 250)`. These are project identity colors only; the single status accent rule from the shipped tokens still holds (overdue/today/In progress marker/focus/drag).
- **DTOs:** `ProjectDto = { id, name, color }`. `TaskDto` gains `projectId: string | null`. `GET /api/board` returns `{ week, projects: ProjectDto[], tasks: TaskDto[] }` with projects ordered by `name asc`.
- **API:** `GET /api/projects` → `ProjectDto[]`; `POST /api/projects` body `{ name: string (trimmed, 1–40), color: ColorKey }` → `201 ProjectDto`; duplicate name (Prisma `P2002`) → `409 { error: "A project with that name already exists" }`. `POST /api/tasks` and `PATCH /api/tasks/[id]` accept `projectId?: string | null`; an unknown id (Prisma `P2003`) → `400 { error: "Unknown project" }`. Routes `force-dynamic`.
- **Dialog (create and edit):** fields in order: Title, Project, Due date, Note, Status. Project is a `<select>` with `No project`, each project (name, with its color dot rendered beside the select), and `New project…`. Choosing `New project…` reveals a name input and eight color swatches (radio group, `aria-label` per color, 24px targets, 44px under pointer-coarse); on Save the dialog first `POST /api/projects`, then creates/updates the task with the returned id; a 409 shows the server error under the form and keeps the dialog open. Create mode: title focused on open, Status preset to the column that opened it, Save label `Add`. Edit mode unchanged otherwise (two-step delete, in-flight disabling).
- **Card:** when `projectId` resolves to a project, the meta row starts with a chip: 8px colored dot (`background: var(--project-<color>)`) plus the project name at 12px in `--muted`, before the due label. Done cards keep the chip at the same 60% opacity as the rest of the card. No chip when there is no project.
- **`+ add` row:** the column footer keeps the muted `+ add` button; it now calls `openCreate(status)`. `components/QuickAdd.tsx` is deleted. Optimistic add stays: the dialog's Save inserts a temp card immediately (60% opacity) and replaces it with the server DTO, same error handling as before.
- **PRODUCT.md:** principle 5 becomes: "No settings, no filters, no tags. If a control does not move a card or change its five fields (title, project, due, note, status), it does not exist." Add Projects to the Product Purpose paragraph in one sentence.

## Task 1: Projects data + API

**Goal:** `Project` table, task relation, DTOs, validation, and routes per Global Constraints.

**Steps:**
1. Schema + migration `projects` (throwaway Postgres as before: container `wt-pg`, host port 5433; `npx prisma migrate dev --name projects`; `docker rm -f wt-pg` after). Migration must be additive (create table, add nullable column, add FK with `ON DELETE SET NULL`).
2. `lib/projects.ts`: `ProjectDto`, `PROJECT_COLORS` (the eight keys, exported as a const tuple), `projectColorSchema = z.enum(PROJECT_COLORS)`, `createProjectSchema`, `listProjects()`, `createProject(input)` (throws Prisma `P2002` through; route maps to 409).
3. `lib/tasks.ts`: `projectId` in `TaskDto`/`toDto`; `createTaskSchema` gains `projectId: z.string().nullish()`; `createTask`/`updateTask` pass it through; `listBoard` returns `projects` (`listProjects()`), and keeps its existing ordering. The `projectId` column is included via scalar field, no `include` needed.
4. Routes: `app/api/projects/route.ts` (GET, POST) using `lib/http.ts` `parseBody`. In `app/api/tasks/route.ts` and `[id]/route.ts`, catch Prisma `P2003` on create/update → `400 { error: "Unknown project" }` (one small helper in `lib/http.ts` is acceptable: `isPrismaError(e, code)`).
5. Live verification (record commands/output): create two projects, duplicate name → 409, create task with `projectId`, PATCH task to `projectId: null`, PATCH with bogus id → 400, `GET /api/board` shows `projects` sorted by name and `projectId` on tasks.
6. `npx tsc --noEmit`, `npm test`, `npm run build`.

**Commit:** `feat: projects with colors on tasks (data + API)`

## Task 2: Dialog-first add + project picker + card chip

**Goal:** UI per Global Constraints (Dialog, Card, `+ add` row, color tokens, PRODUCT.md edit).
