# Spec (verbatim from the user, 2026-10-31)

Build a simple SINGLE-USER weekly to-do kanban tracker. Keep it minimal and fast — no auth, no multi-user, no settings pages. Just a clean board I self-host for myself.

STACK:
- Next.js (App Router, TypeScript) full-stack — React UI + API routes.
- PostgreSQL via Prisma.
- Everything runs through Docker Compose.

CORE FEATURES:
1. Kanban board, 4 columns: Backlog | This Week | In Progress | Done.
2. Task cards: title (required), optional due date, optional note. Create, edit, delete, and move between columns (drag-and-drop with dnd-kit, or a simple status dropdown if that's faster to build reliably).
3. Weekly scoping: "This Week", "In Progress", and "Done" show only the CURRENT ISO week's tasks. "Backlog" is persistent (not week-scoped). Show the current week's date range in the header. Store a `weekOf` field (ISO week start, Monday) on each task.
4. AUTO-ROLLOVER: at the start of each new week (Monday 00:00, timezone Asia/Manila), any task NOT in "Done" that belongs to a past week moves automatically to Backlog (reset weekOf, status=backlog). Past "Done" tasks get archived (archived=true, hidden from the board, kept in DB).
   - Implement with node-cron for the scheduled run, AND run a catch-up pass on app startup (compare each active task's weekOf to the current week and roll over any stale non-done ones) so it self-corrects even if the app was off at the boundary.

REMINDERS (optional, must not block core):
- If TELEGRAM_BOT_TOKEN and TELEGRAM_CHAT_ID env vars are set, a daily cron (9am Asia/Manila) sends a Telegram message listing tasks due today. If those env vars are absent, skip reminders silently — no errors.

DOCKER / PERSISTENCE (important):
- docker-compose.yml with two services: `db` (postgres:16) and `app`.
- Postgres uses a NAMED VOLUME so all data persists across `docker compose down` / `up`.
- `app` waits for Postgres to be healthy (healthcheck), runs `prisma migrate deploy` automatically on startup, then launches. One `docker compose up` must boot the whole stack and retain all previous data.
- Include .env.example with DATABASE_URL and the optional TELEGRAM_* vars.

DELIVERABLES:
- Full working project, start with an empty board (no seed data).
- README with a one-command run section (`docker compose up`).
- Small, readable code. Do NOT add anything beyond the above — ship this exact scope.
